# 设计文档：聊天停止流式传输

## 概述

此设计扩展现有的聊天停止功能，支持在流式传输阶段停止 AI 响应生成，而不仅仅是在初始提交阶段。更改非常小——主要是将控制停止按钮可见性的条件从 `status === 'submitted'` 更新为 `status === 'submitted' || status === 'streaming'`。

## 架构

现有架构保持不变。`@ai-sdk/react` 的 `useChat` hook 已经提供了一个 `stop` 函数，可以在 `submitted` 和 `streaming` 状态下工作。唯一需要的更改是在 UI 层，在流式传输期间显示停止按钮。

```
┌─────────────────────────────────────────────────────────────┐
│                        Chat 组件                             │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                    useChat Hook                          ││
│  │  - status: 'ready' | 'submitted' | 'streaming' | 'error' ││
│  │  - stop(): void (在 submitted 和 streaming 状态下都有效)  ││
│  └─────────────────────────────────────────────────────────┘│
│                              │                               │
│                              ▼                               │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                 MultimodalInput 组件                      ││
│  │  - 从父组件接收 status 和 stop                            ││
│  │  - 当 status 为 submitted 或 streaming 时显示 StopButton  ││
│  │  - 当 status 为 ready 时显示 SendButton                   ││
│  └─────────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────────┘
```

## 组件和接口

### 修改的组件：MultimodalInput

唯一的代码更改在 `components/multimodal-input.tsx`：

```typescript
// 当前实现（约第 324 行）
{status === 'submitted' ? (
  <StopButton setMessages={setMessages} stop={stop} />
) : (
  <PromptInputSubmit ... />
)}

// 新实现
{status === 'submitted' || status === 'streaming' ? (
  <StopButton setMessages={setMessages} stop={stop} />
) : (
  <PromptInputSubmit ... />
)}
```

### 现有接口（无更改）

```typescript
// UseChatHelpers status 类型（来自 @ai-sdk/react）
type ChatStatus = 'ready' | 'submitted' | 'streaming' | 'error';

// Stop 函数签名（已由 useChat 提供）
stop: () => void;
```

## 数据模型

无需更改数据模型。现有的消息结构和聊天状态管理保持不变。

## 正确性属性

*属性是系统所有有效执行中应该保持为真的特征或行为——本质上是关于系统应该做什么的正式声明。属性是人类可读规范和机器可验证正确性保证之间的桥梁。*

### 属性 1：按钮可见性遵循状态

*对于任何*聊天状态值，当且仅当状态为 'submitted' 或 'streaming' 时，停止按钮应该可见；当且仅当状态为 'ready' 时，发送按钮应该可见。

**验证：需求 1.1, 1.2, 1.3**

### 属性 2：停止操作保留已流式传输的内容

*对于任何*具有流式传输内容的聊天会话，当调用停止操作时，所有先前流式传输的消息内容应该保留在消息数组中。

**验证：需求 2.1, 2.2**

### 属性 3：停止后状态转换为 ready

*对于任何*处于 'submitted' 或 'streaming' 状态的聊天会话，调用停止操作应该导致状态转换为 'ready'。

**验证：需求 2.3, 2.4**

### 属性 4：活动生成期间停止按钮处于启用状态

*对于任何*状态为 'submitted' 或 'streaming' 的聊天会话，停止按钮应该处于启用状态（未禁用）并响应点击事件。

**验证：需求 3.1**

### 属性 5：停止后输入字段启用

*对于任何*调用停止的聊天会话，停止操作完成后输入字段应该启用以便输入新消息。

**验证：需求 3.2**

## 错误处理

| 错误场景 | 处理策略 |
|---------|---------|
| 停止操作失败 | 显示错误提示，保持当前状态（useChat 的现有行为） |
| 停止期间网络中断 | 停止是客户端操作，网络状态不影响它 |
| 快速停止/提交循环 | 由 React 状态更新去抖动，无需特殊处理 |

`useChat` hook 的 `onError` 回调中的现有错误处理将处理停止操作期间发生的任何错误。

## 测试策略

### 单元测试

单元测试将验证特定示例和边缘情况：

1. 当状态为 'submitted' 时渲染停止按钮
2. 当状态为 'streaming' 时渲染停止按钮
3. 当状态为 'ready' 时渲染发送按钮
4. 点击停止按钮调用 stop 函数
5. 错误状态显示错误提示（现有行为）

### 属性测试

属性测试将使用 `fast-check` 验证跨多个生成输入的通用属性：

1. **按钮可见性属性**：对于所有有效状态值，验证显示正确的按钮
2. **内容保留属性**：对于所有具有流式传输内容的消息数组，验证停止后内容被保留
3. **状态转换属性**：对于所有活动状态，验证停止后转换为 ready

每个属性测试将运行至少 100 次迭代以确保全面覆盖。

**测试配置：**
- 框架：Vitest 配合 fast-check 进行属性测试
- 标签格式：**Feature: chat-stop-streaming, Property N: [属性描述]**
